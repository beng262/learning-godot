Arrays: things in order

A variable holds one value. A game needs the twelve plots of a farm, the letters in the post, everything in a bag. An array is one variable that holds a row of values, in an order you can count along.

You write an array as a list in square brackets, with commas between the items. Each item has a position, its index, and the first index is 0, not 1.

extends Node

func _ready() -> void:
	var chores := ["water the beans", "feed the dog", "check the post"]
	print(chores)
	print(chores.size(), " chores")
	print("first: ", chores[0])
	print("last:  ", chores[-1])
	chores[1] = "feed the cat"
	print(chores)

chores[0] reads the item at index 0, and chores[1] = … replaces the one at index 1. A negative index counts back from the end, so [-1] is always the last item however long the list is. Press Edit and run and add a fourth chore: size() and [-1] follow without being told.

Counting from 0 means three items have the indexes 0, 1 and 2. There is no item 3, and asking for it is the first of this chapter's two errors:

extends Node

func _ready() -> void:
	var chores := ["water the beans", "feed the dog", "check the post"]
	print(chores[3])

Godot stops on that line and says the index is out of bounds. It is nearly always a loop that went one step too far, or a list that was emptier than you thought. The last valid index is size() - 1.

Adding and taking away

An array grows and shrinks while the game runs. The methods are named for what they do:

extends Node

func _ready() -> void:
	var basket := ["carrot", "tomato"]
	basket.append("pumpkin")          # on the end
	basket.insert(0, "strawberry")    # at index 0; the rest move up one
	print(basket)

	basket.erase("tomato")            # the first item equal to this
	basket.remove_at(0)               # whatever is at this index
	print(basket)

	var last = basket.pop_back()      # take the last one off and hand it over
	print(last, " taken, leaving ", basket)
	print(basket.has("carrot"), " ", basket.find("carrot"), " ", basket.find("koi"))

The last line prints true 0 -1: the basket has a carrot, it is at index 0, and find() answers -1 for something that is not there. Change erase("tomato") to erase("koi"): nothing happens and nothing complains, because erasing a value that is absent is not an error.

MethodWhat it does

erase(x)Removes the first item equal to x.

Saying what is in it

A plain Array will hold anything, mixed: a number, a string and another array can sit side by side. Mostly you want the opposite, a list of one kind of thing, and you can say so. Array[int] is an array that holds only whole numbers:

extends Node

var scores: Array[int] = [40, 12, 77]

func _ready() -> void:
	scores.append(55)
	scores.sort()
	print(scores)
	print("best ", scores.back(), ", worst ", scores.front())
	print("top two: ", scores.slice(-2))

A typed array does for a list what a type does for a variable (Chapter D): the editor can complete and check what you do with the items, and Godot refuses to put a String into an Array[int] instead of letting it sit there until something adds it up. front() and back() are the first and last items; after a sort() they are the smallest and the largest.

Walking a list with for

A list is only useful if you can do something with every item in it. Chapter E gave you for; an array is what it was made for.

extends Node

var prices := [18, 18, 22, 26]

func _ready() -> void:
	var total := 0
	for p in prices:
		total += p
	print("total: ", total)

	for i in prices.size():
		print(i, " -> ", prices[i])

Those are the two shapes. for p in prices hands you each item in turn and is the one to reach for first. for i in prices.size() counts 0, 1, 2, 3 and hands you each index; use it when you need to know where you are, or when you want to change the items.

That second reason is a small trap. The loop variable is a copy of the item, so changing it changes nothing in the list:

extends Node

func _ready() -> void:
	var prices := [18, 18, 22]
	for p in prices:
		p += 1            # changes p, the loop's own copy
	print(prices)

	for i in prices.size():
		prices[i] += 1    # changes the list
	print(prices)

Choosing and changing in one line

Two jobs come up so often that arrays do them for you. filter() keeps the items that pass a test, and map() makes a new array by doing something to each item. Both take a function, usually a lambda from Chapter F, and both leave the original alone:

extends Node

func _ready() -> void:
	var grams := [120, 340, 80, 410]
	var heavy := grams.filter(func(g): return g > 300)
	var kilos := grams.map(func(g): return g / 1000.0)
	print(heavy)
	print(kilos)
	print(grams)

Change 300 to 100 and three of the four pass. Anything filter does, a for loop with an if and an append does too; use whichever you can read at a glance.

Do not change a list while you walk it

Here is a loop that pulls the weeds out of a bed. Predict what it prints before you run it.

extends Node

func _ready() -> void:
	var bed := ["weed", "weed", "carrot", "weed"]
	for plant in bed:
		if plant == "weed":
			bed.erase(plant)
	print(bed)

One weed survives. The loop keeps its place by counting, and every erase closes the gap, so the item that slides into the place you are standing on is never looked at. Godot's documentation says it plainly: erasing while iterating is not supported, for arrays and for dictionaries. There are two honest ways to do it. Build the list you want instead of cutting down the one you have:

extends Node

func _ready() -> void:
	var bed := ["weed", "weed", "carrot", "weed"]
	bed = bed.filter(func(plant): return plant != "weed")
	print(bed)

Or walk a copy and change the original: for plant in bed.duplicate():. The loop stands on the copy, which nobody is erasing from.

Dictionaries: looking things up

An array answers "what is third?". Most questions in a game are not like that. They are "how many carrots?", "what does a pumpkin cost?", "where did I leave the lamp?" – a name in, a value out. That is a dictionary.

A dictionary holds pairs: a key and the value kept under it. You write it in curly brackets with a colon inside each pair, and you read and write it with square brackets, as you do an array, except that what goes in the brackets is the key.

extends Node

func _ready() -> void:
	var bag := {"carrot": 3, "tomato": 1}
	print(bag["carrot"])
	bag["pumpkin"] = 2          # a new key: the pair is added
	bag["carrot"] += 1          # an old key: its value is changed
	print(bag)
	print(bag.size(), " kinds of thing")

Assigning to a key that is not there creates it; assigning to one that is there replaces its value. There is no append, because there is no end to add to. Keys are usually strings, but any value will do: a number, or the Vector2i of a cell on a grid.

Reading a key that is not there is the chapter's second error:

extends Node

func _ready() -> void:
	var bag := {"carrot": 3}
	print(bag["koi"])

So when a key may be missing, and in a bag it usually may, you ask instead of assuming:

extends Node

func _ready() -> void:
	var bag := {"carrot": 3}
	print(bag.get("koi", 0))            # the value, or 0 if there is no such key
	print(bag.has("koi"), " ", "carrot" in bag)

	bag["koi"] = bag.get("koi", 0) + 1  # safe "add one", whether or not it was there
	bag.erase("carrot")
	print(bag)

get(key, fallback) is the method you will type most. The line that adds one koi is worth learning as a shape: bag["koi"] += 1 would have stopped with the same error, because it has to read the old value before it can add to it.

You writeWhat it does
d[key]Reads the value (an error if the key is missing), or with = writes it.
d.get(key, fallback)Reads the value, or gives you fallback if the key is missing.
d.has(key), key in dIs there such a key?
d.erase(key)Removes the pair.
d.size(), d.is_empty()How many pairs, and whether that is none.
d.keys(), d.values()A new array of all the keys, or all the values.
d.duplicate()A copy, as for arrays.

Walking a dictionary

for over a dictionary gives you its keys, in the order they were added. With the key you can fetch the value:

extends Node

func _ready() -> void:
	var bag := {"carrot": 3, "tomato": 1, "pumpkin": 2}
	var things := 0
	for key in bag:
		print(key, " x", bag[key])
		things += bag[key]
	print(things, " things in all")

Tables: dictionaries inside dictionaries

A value can be anything, including another dictionary or an array. That turns a dictionary into a table: one row for each key, and the same few fields in every row. This is the whole list of what you can grow in Little Hours:

Game.gd · lines 257–263

const CROPS := {
	"carrot":     {"name": "Carrot",     "grow": 15.0},
	"tomato":     {"name": "Tomato",     "grow": 20.0},
	"strawberry": {"name": "Strawberry", "grow": 25.0},
	"sunflower":  {"name": "Sunflower",  "grow": 30.0},
	"pumpkin":    {"name": "Pumpkin",    "grow": 40.0},
}

Two sets of square brackets read one cell: the row, then the field. Here is a shorter copy to try it on.

extends Node

const CROPS := {
	"carrot":  {"name": "Carrot",  "grow": 15.0},
	"tomato":  {"name": "Tomato",  "grow": 20.0},
	"pumpkin": {"name": "Pumpkin", "grow": 40.0},
}

func _ready() -> void:
	print(CROPS["tomato"]["name"])
	for key in CROPS:
		var crop: Dictionary = CROPS[key]
		print("%s ripens in %s seconds" % [crop["name"], crop["grow"]])

Add a row for "sunflower" and the loop prints it. Nothing else in the script has to know that there are now four crops, and that is the reason to keep facts in a table and not in a chain of ifs. Chapter V is about designing a whole game that way.

Which one?

Use an Array whenUse a Dictionary when

And they combine. A list of records is an array of dictionaries, which is how the grocer's shelf is written in the game: four rows, in shelf order, each with a "key" and a "price".

extends Node

var shelf := [
	{"key": "carrot", "price": 18},
	{"key": "tomato", "price": 18},
	{"key": "strawberry", "price": 22},
	{"key": "pumpkin", "price": 26},
]

func _ready() -> void:
	for row in shelf:
		if row["price"] > 20:
			print(row["key"], " costs ", row["price"])
	shelf.sort_custom(func(a, b): return a["price"] > b["price"])
	print("dearest first: ", shelf.map(func(row): return row["key"]))

sort() has no way to know which field you want the rows ordered by, so sort_custom() takes a function that is given two items and answers "does the first belong before the second?". Turn the > into < to put the cheapest first.

Shared, or copied?

Numbers, strings, vectors and colours are copied when you assign them. Arrays and dictionaries are not: assigning one gives you a second name for the same thing. Almost every baffling bug with collections is this.

extends Node

func _ready() -> void:
	var a := 5
	var b := a
	b += 1
	print(a, " ", b)

	var mine := ["carrot"]
	var yours := mine
	yours.append("tomato")
	print(mine)

The first pair behaves as you expect: b got its own 5, and adding to it leaves a alone. The second pair does not. yours := mine did not make a second list. It made a second reference to the one list, so what you append through yours is there when you look through mine.

The same happens when you pass an array or a dictionary to a function: the function receives the list itself, not a copy of it.

extends Node

func plant_weeds(bed: Array) -> void:
	bed.append("weed")

func _ready() -> void:
	var garden := ["rose"]
	plant_weeds(garden)
	plant_weeds(garden)
	print(garden)

This is not a flaw. It is what lets a function fill in a list for you, and it is why handing a ten-thousand-item array to a function costs nothing. You only have to know it is happening.

The trap

A farm is a row of plots, and each plot is a small dictionary. This builds three of them, then tills the first. Predict the output.

extends Node

func _ready() -> void:
	var plot := {"state": "grass", "crop": ""}
	var farm := []
	for i in 3:
		farm.append(plot)

	farm[0]["state"] = "tilled"
	print(farm)

All three are tilled, because there are not three plots. There is one dictionary, and the array holds three references to it. The curly brackets ran once, so one dictionary was made.

The cure is to make a new dictionary each time round. Move the var plot := {…} line inside the loop, above the append, and run it again: now the brackets run three times and only the first plot is tilled. A function that returns a dictionary written out in full does the same job, since each call builds a fresh one.

duplicate()

When you do want a copy of something that already exists, you ask for one. duplicate() returns a new array or dictionary with the same contents.

extends Node

func _ready() -> void:
	var room := {"name": "kitchen", "things": ["stove", "table"]}
	var shallow := room.duplicate()
	var deep := room.duplicate(true)

	shallow["name"] = "pantry"          # its own top level...
	shallow["things"].append("jar")     # ...but the list inside is still shared
	deep["things"].append("ghost")      # a deep copy shares nothing

	print(room)
	print(shallow)
	print(deep)

Read the three lines of output slowly. Plain duplicate() is a shallow copy: a new outer dictionary whose values are the same values, so an array inside it is still the one array. That is why the jar turned up in the kitchen. duplicate(true) is a deep copy, which copies the arrays and dictionaries inside as well, all the way down. For a flat list of numbers the two are the same; for anything nested, decide which you mean.

A const table cannot be changed

An array or dictionary declared with const is read-only in Godot: calling append() on it, or assigning to one of its keys, is an error when the line runs. That is what you want of a table of facts such as CROPS. When you need a version you can change, take a duplicate() of it and change that. The interpreter in this book does not enforce the rule, so do not lean on it here; Godot will.

Every shape from this chapter is there. A plain number under "coins". Three bags, "crops", "dishes" and "fish", each a dictionary from a name to a count. A dictionary of dictionaries under "records". Arrays where order matters: "memories" and "gallery" both keep the newest first, because each new entry is put in with insert(0, …). The comments are the documentation: a dictionary cannot say what shape it expects, so the code says it beside each key.

Keeping everything in one dictionary has a large pay-off: saving the game is turning that one value into text, and loading is reading it back. Chapter S and Saving follow that thread.

The bag

You wrote these two in the tutorial. Here are the originals:

func count_of(kind: String, key: String) -> int:
	return int((state[kind] as Dictionary).get(key, 0))

kind chooses which bag: "crops", "dishes" or "fish". The line var bag: Dictionary = state[kind] is the idea of the fourth section put to work. It does not copy the bag out of state; it gives the bag inside state a short local name. So bag[key] = … on the next line changes the saved game, with no line needed to put anything back.

There is no separate "remove" function. n may be negative, which is how cooking uses up a carrot, and the if erases a key that has reached zero. _changed() at the end announces that the state changed and writes the save. Items has the rest of the bag, and Jobs and money what selling does with it.

Twelve plots that really are twelve

The farm is the last key of the state, "farm": _fresh_farm(): an array of plots, each a dictionary of five facts.

Game.gd · lines 627–628

func _fresh_plot() -> Dictionary:
	return {"state": "grass", "crop": "", "planted_at": 0.0, "watered": false, "ready": false}

Game.gd · lines 630–634

func _fresh_farm() -> Array:
	var a: Array = []
	for i in range(FARM_COLS * FARM_ROWS):
		a.append(_fresh_plot())
	return a

This is the trap from earlier, avoided. _fresh_plot() is a function, so each call runs the curly brackets again and returns a new dictionary; the loop calls it once for every cell of a field FARM_COLS by FARM_ROWS, four by three. Had it made one plot above the loop and appended that twelve times, watering one plot would have watered the field. The farm is an array, not a dictionary, because a plot's index is its place in the grid. Farming shows what tilling, planting and watering write into those five keys.

What to remember

  • An Array is values in order, counted from 0; [-1] is the last. A Dictionary is values under keys. Use the first when order matters and the second when you look things up by name.
  • Reading an index past the end, or a key that is not there, is an error. size() guards the first; get(key, fallback) and has(key) guard the second.
  • for item in array walks the items, for key in dictionary walks the keys. Do not add to or erase from the thing you are walking: build a new one, or walk a copy.
  • Assigning or passing an array or a dictionary shares it. duplicate() makes a copy, and duplicate(true) also copies what is nested inside.
  • Curly or square brackets make a new collection each time they run. One literal appended twelve times is one thing with twelve names.
  • A dictionary of small dictionaries is a table, and a game whose facts live in tables grows by adding rows, not code.
