Values and their types

Everything a game knows is a value: how many coins, how fast, whose house, is the door open. Every value has a type, and the type decides what you are allowed to do with it.

In Chapter A you printed some text and a sum without asking what kind of thing either was. Ask now. Run this:

extends Node

func _ready() -> void:
	print(12)        # an int: a whole number
	print(2.5)       # a float: a number with a decimal point
	print("Wren")    # a String: text, between double quotes
	print(true)      # a bool: true or false, nothing else

Anything after a # on a line is a comment: a note for people, which Godot ignores. The four values on those lines are the four basic types, and most of a game is built from them.

TypeWhat it holdsWritten likeUsed for
inta whole number, positive or negative0, 12, -3things you count: coins, days, tiles
floata number with a fractional part2.5, 0.0, -0.75things you measure: seconds, speeds, shares
Stringtext"Wren", "Day 3", ""names, messages, anything shown as words
boolone of two answerstrue, falseswitches: is it night, has she got the key

The type is part of the value. 7 and 7.0 are the same amount but not the same kind of thing: the first is an int and the second is a float. "7" is neither – it is a piece of text that happens to contain a digit. Godot shows you which number you have, because a float always prints with a decimal point:

extends Node

func _ready() -> void:
	print(7)
	print(7.0)
	print(3 + 4)       # int + int stays an int
	print(3 + 4.0)     # one float in a sum makes the answer a float
	print(2 * 1.5)

Press Edit and run and change the 4.0 to 4: the .0 on the fourth line goes. Adding, subtracting and multiplying all follow that rule – two ints give an int, and a float anywhere gives a float. Division has a rule of its own, and it gets a whole section below.

Variables: a name for a value

A value you cannot refer to again is not much use. A variable is a name with a value kept under it, so the script can read the value later and change it.

extends Node

var coins = 12

func _ready() -> void:
	print(coins)
	coins = 20
	print(coins)
	coins = coins + 5
	print(coins)
	coins += 1
	print(coins)

var makes the variable. After that, a single = is an instruction, not a statement of fact: work out what is on the right, then keep it under the name on the left. That is why coins = coins + 5 is not nonsense. It reads "take what coins holds now, add five, and keep the answer under coins". Changing a variable by an amount is so common that it has a short form, coins += 5, with -=, *= and /= beside it.

Names

A name is made of letters, digits and underscores, and cannot start with a digit. Capitals matter: coins and Coins are two different names. GDScript's habit is snake_case for variables – small letters, words joined with underscores – so max_health, not maxHealth. Spend a moment on names. days_left explains itself six months from now and d does not.

The first error most people meet is a name typed slightly wrong. This one stops:

extends Node

var coins = 12

func _ready() -> void:
	print(coin)

Read the message rather than the red: Identifier "coin" not declared in the current scope. An identifier is a name; not declared means no var ever made it; and it tells you the line. Godot is not being difficult – it has no way to know that coin was meant to be coins, and guessing would be worse. In the Godot editor the line is marked before you ever press run. Add the s and it works.

Giving a variable a type

The coins above was made with a plain =, and a variable made that way will hold anything at all. That sounds convenient. Watch what it costs:

extends Node

var coins = 12

func _ready() -> void:
	coins = "lots"        # allowed: this variable takes anything
	print(coins - 5)      # ...and the mistake comes out here instead

The mistake was putting text into coins. The error is reported two lines later, where something tried to subtract from it – and in a real game that line could be in another file, an hour of play away. The cure is to say what the variable is for, by giving it a type:

extends Node

var coins: int = 12

func _ready() -> void:
	coins = "lots"
	print(coins - 5)

Now the error is on the line that is actually wrong, and in the editor it appears while you type, before the game runs at all. var coins: int = 12 reads "a variable called coins, which is an int, starting at 12".

Writing the type every time is a chore when the starting value already makes it obvious, so GDScript has a third form. := means work the type out from the value, and then hold me to it:

var coins := 12             # an int, because 12 is an int
var speed := 1.5            # a float
var player_name := "Wren"   # a String
var is_open := true         # a bool
You writeYou getLater, coins = "lots" is
var coins = 12an untyped variableallowed
var coins: int = 12an int variable, type written outan error
var coins := 12an int variable, type worked outan error

Use := as your everyday form – Little Hours does, almost everywhere. Write the type out in two cases: when there is no starting value to work it out from, and when the value's own type is not the one you want.

extends Node

var day: int               # no value given: an int starts at 0
var speed: float = 3       # the 3 becomes 3.0 to fit
var player_name: String    # a String starts empty
var is_open: bool          # a bool starts false
var anything               # untyped and empty: null, which means "nothing here"

func _ready() -> void:
	print(day)
	print(speed)
	print(player_name)
	print(is_open)
	print(anything)

The third line of output is blank: that is the empty String being printed. A variable of one of these types always starts at that type's own zero. An untyped one starts as null.

Where a variable lives

A variable made at the left edge of the script, outside every function, belongs to the script. It exists for as long as the node does, and every function in the script can read and change it. A variable made inside a function is local: it exists from its own line to the end of that function, and nothing outside can see it.

extends Node

var coins := 12            # belongs to the script

func _ready() -> void:
	var price := 5         # belongs to _ready() only
	coins -= price
	print(coins)

That is what "the current scope" in the error message meant: the names visible from where a line is standing. Keep what the whole script needs to remember at the top, and everything else local. Chapter F comes back to this.

Numbers, and the integer division trap

Having two kinds of number sounds like a detail. It is the cause of the best-known beginner bug in Godot, so meet it here on purpose rather than at midnight by accident.

extends Node

func _ready() -> void:
	print(7 / 2)       # both ints
	print(7.0 / 2)     # one float
	print(7 / 2.0)     # the other one a float
	print(6 / 2)       # divides evenly, and is still an int

An int divided by an int is an int. The fractional part is not rounded, it is thrown away: 7 / 2 is 3, and 99 / 100 is 0. This is integer division. Nothing stops, nothing turns red, and the number is wrong.

Where it bites

The classic case is a share of something: how full is the health bar? Both numbers are whole, so both are ints, so the answer is too:

extends Node

var health := 30
var max_health := 120

func _ready() -> void:
	var fraction := health / max_health
	print(fraction)
	print(fraction * 100, "% full")

A quarter full, and it prints 0. A bar drawn from that number is empty all game and then jumps to full when health reaches 120. Fix it yourself: press Edit and run and change the division to float(health) / max_health. float() turns a value into a float, and one float is enough to make the whole division keep its fraction.

There are three ways out, and you will use all of them:

var a := float(health) / max_health    # convert one side as you divide
var b := health / 2.0                  # write a number with a decimal point
var health := 30.0                     # or make it a float from the start

The editor does warn you

Godot puts a yellow warning beside any line that divides one int by another, saying the decimal part will be discarded. Warnings do not stop the game, which makes them easy to ignore. Read them: this one is nearly always right.

When you want it

Integer division is the right tool when the question is "how many whole ones?". How many whole hours in 135 minutes:

extends Node

func _ready() -> void:
	var minutes := 135
	var hours := minutes / 60              # whole hours
	var left := minutes - hours * 60       # what is over
	print(hours, " h ", left, " min")

Change 135 to 59, then to 60. Chapter E has an operator, %, that gets the left-over part in one step.

In Little Hours

A year in the game is twenty days, and which year you are in is worked out by integer division on purpose:

Game.gd · lines 1818–1820

## Which year you are in, counting the one you arrived in as the first.
func year() -> int:
	return (maxi(1, int(state["day"])) - 1) / DAYS_PER_YEAR + 1

state["day"] is the day number, looked up in the game's saved state (Chapter G), and maxi(1, …) makes sure it is never below one. DAYS_PER_YEAR is 20. Days 1 to 20 give 0 to 19 after the - 1, and every one of those divided by 20 is 0, so they are all year 1. Day 21 gives 20 / 20, which is 1: year 2. Throwing the remainder away is exactly the point.

From a float back to an int

Going the other way, you have to say what should happen to the fraction:

extends Node

func _ready() -> void:
	print(int(3.9))       # cut the fraction off
	print(int(-3.9))      # ...towards zero, not downwards
	print(roundi(3.9))    # nearest whole number
	print(floori(3.9))    # always down
	print(ceili(3.1))     # always up
	print(round(3.9))     # without the i, the answer stays a float

int() does not round. A score of 3.9 shown with int() reads 3, and a typed variable does the same thing silently: put 2.9 into a variable declared int and it holds 2.

Floats are close, not exact

extends Node

func _ready() -> void:
	print(0.1 + 0.2)
	print(0.1 + 0.2 == 0.3)
	print(is_equal_approx(0.1 + 0.2, 0.3))

The sum prints as 0.3 and is still not equal to 0.3. A float is stored in binary, and a tenth cannot be written exactly in binary any more than a third can in decimal, so tiny errors creep in. Two rules follow. Never ask whether two floats are equal after arithmetic: use is_equal_approx(), or ask >=. And count with ints: coins, days and lives are whole things, an int is always exact, and nobody wants 4.999999 coins.

Text, true and false, and changing type

Strings join with +, and only with other Strings. That one rule produces the error you will see more often than any other.

extends Node

func _ready() -> void:
	var first := "Little"
	var second := "Hours"
	var title := first + " " + second
	print(title)
	print(title.length())
	print(title.to_upper())
	print("She said \"hello\".\nThen she left.")

+ between two Strings glues them end to end, and it adds no space of its own. A String also has methods, jobs it can do, called with a dot: .length(), .to_upper() and dozens more. Inside the quotes a backslash starts a special character: \" is a quote mark that does not end the String, and \n is a new line.

Now join a number on:

extends Node

func _ready() -> void:
	var coins := 5
	print("You have " + coins + " coins")

The error names two types and an operator: a String and an int cannot be added. Godot will not guess whether "5" + 5 should be "55" or 10, so you say which. Here are three ways, all of which print the same line:

extends Node

func _ready() -> void:
	var coins := 5
	print("You have " + str(coins) + " coins")   # str() turns any value into text
	print("You have ", coins, " coins")           # print() takes several things, separated by commas
	print("You have %d coins" % coins)            # a format string: %d is a gap for a whole number

Format strings

The third way is the one to learn for anything shown to a player. The text is written whole, with gaps, and % fills the gaps in. %s takes any value, %d a whole number, %.1f a float with one decimal place. Several values go in square brackets, in order:

extends Node

func _ready() -> void:
	var who := "Wren"
	var coins := 5
	print("%s has %d coins" % [who, coins])
	print("%02d:%02d" % [9, 5])
	print("%.1f seconds" % 12.3456)

%02d means "a whole number, at least two characters wide, padded with zeros", which is how a clock gets 09:05 instead of 9:5. Change %.1f to %.3f and see what it keeps.

Text into numbers

extends Node

func _ready() -> void:
	print("5" + "5")              # two pieces of text, joined
	print(int("5") + int("5"))    # two numbers, added
	print(float("2.5") * 2)
	print(int("five"))            # text that is not a number becomes 0, without complaint

str(), int() and float() are the three converters, and you now know all of them. Mind the last line: int() of text that is not a number gives 0 and no error, so check what a player typed before you trust it.

bool: the answer to a question

A bool is what a comparison gives back. You can print it, and you can keep it in a variable like any other value:

extends Node

func _ready() -> void:
	var coins := 5
	var price := 8
	var can_buy := coins >= price
	print(can_buy)
	print(coins == 5)
	print(not can_buy)

Two equals signs ask whether two things are equal; one equals sign stores. Mixing them up is the third classic mistake of week one. Name a bool so that it reads as a question with a yes or no answer – is_open, has_key, can_buy – and the code that uses it will read like a sentence. Chapter E builds decisions out of them.

Vector2 and Color: values with parts

A position is two numbers that always travel together. A colour is four. Godot gives each a type of its own, so one variable holds the whole thing and arithmetic works on all the parts at once.

Vector2

extends Node

func _ready() -> void:
	var spot := Vector2(100, 50)
	print(spot)
	print(spot.x)
	spot.x += 20
	spot += Vector2(0, 10)
	print(spot)
	print(spot * 2)
	print(Vector2(3, 4).length())

A Vector2 has an x and a y, both floats, reached with a dot. On the screen x runs to the right and y runs down: adding to y moves a thing towards the bottom of the window, which surprises everyone once. Adding two vectors adds their parts, multiplying by a number scales both, and .length() is how far the point is from zero. The common ones have names: Vector2.ZERO, Vector2.ONE, and the four directions Vector2.LEFT, Vector2.RIGHT, Vector2.UP and Vector2.DOWN – where UP is (0, -1), because up the screen is less y.

There is a whole-number version, Vector2i, for things that are counted in both directions: a cell on a grid, a size in pixels. Its parts are ints, so the trap from the last section comes with it:

extends Node

func _ready() -> void:
	var cell := Vector2i(7, 7)
	print(cell / 2)
	print(Vector2(7, 7) / 2)

Color

extends Node

func _ready() -> void:
	var amber := Color(1.0, 0.5, 0.25)        # red, green, blue: each from 0.0 to 1.0
	var rose := Color("#e0808f")              # or the hex code a paint program gives you
	var glass := Color(1, 1, 1, 0.5)          # a fourth number is alpha: 0 is clear, 1 is solid
	print(amber.g)
	print(glass.a)
	print(rose.to_html(false))
	print(rose.darkened(0.3).to_html(false))
	print(Color.RED.to_html(false))

A Color has four parts, r, g, b and a, each a float between 0 and 1 rather than the 0 to 255 you may know from elsewhere. You can make one from the parts, from a hex string, or by name (Color.RED, Color.WHITE and many more). Like a String it has methods: .darkened(0.3) gives back a new colour thirty per cent darker, .lightened() is its opposite, and .to_html(false) writes the colour back out as hex – the false leaves the alpha off. Change 0.3 to 0.6 and watch the hex numbers fall.

Each variable has its own copy

extends Node

func _ready() -> void:
	var a := Vector2(1, 2)
	var b := a          # b gets a copy of a
	b.x = 99
	print(a)
	print(b)

Changing b left a alone. Every type in this chapter behaves that way: putting a value in a second variable copies it. It is worth noticing now, because the lists and lookups of Chapter G do not, and that difference catches people.

Constants and enums: names that stay put

Some values are decided once, by you, and never change while the game runs: the size of a tile, the length of a day. Give them names too, and tell Godot that they are fixed.

extends Node

const TILE := 96
const COLS := 8
const STAGE_W := TILE * COLS      # a constant can be built from other constants

func _ready() -> void:
	print(STAGE_W)
	print(3 * TILE)

A const is made like a variable and read like a variable. The difference is that it cannot be given a new value, ever:

extends Node

const TILE := 96

func _ready() -> void:
	TILE = 100

That refusal is the feature. A constant buys you three things. The number has a name, so 3 * TILE says what it means where 288 says nothing. It lives in one place, so making tiles 64 pixels is one edit rather than a hunt through every file for the right 96s. And nothing can change it by accident halfway through a game.

Constants are written in capitals with underscores, so they stand out wherever they are used. Their value has to be known before the game starts – a number, a String, a sum of other constants – not something worked out while playing. The test for which to use is one question: does this change while the game runs? Coins do, so var. The tile size does not, so const.

Enums: one of a fixed set

Often a value is a choice from a short list: the weather is clear, rainy or snowy, and nothing else. You could keep it as a String, but "rainny" is a perfectly good String, and code that compares against it will be quietly wrong for ever. An enum is a list of names that Godot knows about:

extends Node

enum Weather { CLEAR, RAINY, SNOWY }

var today := Weather.RAINY

func _ready() -> void:
	print(today)                       # an enum value is an int underneath
	print(today == Weather.RAINY)
	print(Weather.keys()[today])       # the name, for when you need to show it
	today = Weather.SNOWY
	print(today)

The names are numbered from zero in the order you wrote them, so Weather.CLEAR is 0, RAINY is 1 and SNOWY is 2, and that is what prints. You hardly ever care about the numbers: you write Weather.RAINY and compare with ==. What you gain over a String is that a misspelt Weather.RAINNY is an error the moment you type it, and the editor offers the three names as you write the dot. What you gain over a bare 1 is that the code can be read.

An enum is also a type, so a variable can be limited to it: var today: Weather = Weather.CLEAR. And when the numbers do matter you can set them: in enum Level { LOW = 1, MID = 5, HIGH }, HIGH carries on from the one before and is 6.

Build it live

One script, six small steps, and every type in this chapter used for what it is good at. You are going to describe a room entirely in data.

In Little Hours

Little Hours keeps its decisions at the top of its files as constants, and the comments beside them are a record of every time a number was wrong.

The numbers from the tutorial are real. This is the top of Game.gd, the script that holds the game's state and rules (Inside the code):

Game.gd · lines 20–23

# ── The world grid (identical to the web build, so layouts port 1:1) ──
const TILE := 96
const STAGE_W := 768    # 8 tiles
const STAGE_H := 1344   # 14 tiles

Three int constants, each made with :=, and a comment giving the stage in tiles so nobody has to divide by 96 in their head. Everything in a room is placed on that grid. The clock has its pair further down the same file: const DAY_LENGTH := 480.0, a float because it is measured in seconds, and const DAYS_PER_SEASON := 5, an int because days are counted. The first is why a day is 480 seconds of the game's clock (C: Clock), and a year is twenty days because DAYS_PER_YEAR is written as DAYS_PER_SEASON * 4: a constant built from a constant, like STAGE_W in this chapter (Y: Years).

Integer division, meant

The game's art can be drawn at full size or at half, and one number in Assets.gd decides which (Inside the code):

Assets.gd · lines 46–50

const DENSITY_DIV := 2

## One stored scale, divided by the dial. Whole in, whole out.
static func scaled(base: int) -> int:
	return maxi(1, base / DENSITY_DIV)

base / DENSITY_DIV is an int divided by an int, and here that is wanted. Pixel art has to be drawn at a whole-number scale or its pixels smear, so a scale of 6 becomes 3, a scale of 5 would become 2, and maxi(1, …) – the larger of the two numbers – stops it ever reaching 0. The comment says it in four words: whole in, whole out.

Integer division, avoided

A few lines of Game.gd turn that whole number into the camera's zoom, which is a ratio and must not lose its fraction:

Game.gd · lines 104–109

## The camera's zoom, from the lean above. Whole in, whole out.
func camera_zoom() -> float:
	var art: int = Assets.scaled(6)
	if art <= 0:
		return 1.0
	return float(art + CAMERA_LEAN) / float(art)

art is 3 and CAMERA_LEAN is the constant 1, so the answer wanted is 4 / 3, about 1.33. As ints that division gives 1 – no zoom at all, and no error to say why. So both sides are wrapped in float() before the division, exactly as you did for the wall. Notice the declared types as well: var art: int states what comes back from another file, and -> float states what this function hands out (Chapter F). How the zoom is used is in O: Orientation and camera.

Colours with names, and a var that used to be a const

Every colour in the interface is a named Color at the top of UI.gd (Inside the code):

UI.gd · lines 12–25

# These are `static var`, not `const`, because the player can change the theme
# (More ▸ Look). Every colour below is reassigned by `apply_theme()`, and the
# cached Theme is thrown away so it rebuilds on the next `theme()` call.
# Read them the same way as before — `UI.ACCENT` etc. still works everywhere.
static var CREAM      := Color("#fdf0f2")
static var PANEL      := Color("#fffafb")
static var PANEL_DEEP := Color("#fbe4e8")
static var BORDER     := Color("#f0c7d0")
static var INK        := Color("#4c3438")
static var INK_SOFT   := Color("#8a6b73")
static var ACCENT     := Color("#e0808f")
static var ACCENT_INK := Color("#ffffff")
static var COOL       := Color("#7ea8c6")
static var GOOD       := Color("#7fae72")

Each is made from a hex code, as wall_colour was. They are named in capitals because they began life as constants, and the comment explains why they are not any more: the player can pick another theme, so the values have to change while the game runs. That is the one-question test from earlier, applied honestly. (static makes a variable belong to the script itself rather than to one node – Chapter U.) The same thing happened in Game.gd, where the walkable floor and the place you appear are declared var BOUNDS := Rect2(…) and var SPAWN := Vector2(360, 1150) with a note that they stopped being const when the room could be turned on its side. The interface built from these colours is U: UI.

One thing you will not find: there is no enum anywhere in Little Hours. Where this chapter used one, the game uses Strings – a farm plot's state is "grass", "tilled" or "planted". Those words go into the save file as they are, which keeps it readable, and the price is the one you saw: a misspelt state is not an error. Both are reasonable choices; know which one you are making.

Your turn

Six exercises, from warming up to a small piece of real game arithmetic. The checks look at the values and their types, so 25 and "25" are not the same answer.

What to remember

  • Every value has a type. Count with int, measure with float, write with String, answer with bool; Vector2 and Color hold several numbers as one value.
  • var x := value makes a variable and fixes its type from the value. Write var x: Type when there is no value to go by. An untyped var x = value moves errors away from their cause.
  • An int divided by an int is an int: 7 / 2 is 3. Put float() round one side, or write 2.0, whenever you want the fraction – and use it on purpose when you want whole ones.
  • Strings only join with Strings. str(), int() and float() convert, and "%d coins" % n fills a gap.
  • = stores, == asks. Floats are close, not exact: do not test them with ==.
  • const for what never changes while the game runs, enum for a choice from a fixed list. Both turn a typing mistake into an error instead of a bug.
