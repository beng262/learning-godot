Expressions and decisions

Operators, if, elif and else, match, loops with for and while, and what counts as true.

Expressions and operators

An expression is anything Godot can work out to a single value. 12 is one. So are coins, coins + 5 and coins >= price. Wherever a value is wanted, an expression will do, and operators are the symbols that build bigger ones from smaller ones.

Arithmetic, and what happens first

extends Node

func _ready() -> void:
	print(2 + 3 * 4)       # multiplying comes before adding, as at school
	print((2 + 3) * 4)     # brackets come before everything
	print(10 - 4 - 3)      # equal rank: left to right
	print(2 ** 10)         # ** is "to the power of"

You met +, -, * and / in Chapter D, with the rule about ints and floats. When several appear in one expression, ** is done first, then *, / and %, then + and -, and operators of the same rank go left to right. You do not have to remember any of that: brackets cost nothing, and (hours * 60) + minutes says what you mean to the next reader as well as to Godot.

% – what is left over

Integer division throws the remainder away. % is the operator that keeps it. The two are halves of the same sum: how many whole ones, and what is over.

extends Node

func _ready() -> void:
	var minutes := 135
	print(minutes / 60, " h ", minutes % 60, " min")
	print(7 % 2)       # seven is odd
	print(8 % 2)       # eight is even
	print(23 % 7)      # day 23 is two days into its week

That small operator does three jobs you will want all the time:

  • Splitting a total into units. Minutes into hours and minutes, coins into notes and change.
  • Testing whether one number divides another. n % 2 == 0 means "n is even"; day % 7 == 0 means "every seventh day".
  • Wrapping round. n % 4 is always 0, 1, 2 or 3, however big n gets, so a counter that keeps climbing can still pick one of four seasons.

Change 23 to 28, then 29. % works on ints only; give it a float and Godot stops and tells you to use fmod() instead.

Changing a variable in place

coins += 5 from the last chapter has a family: -=, *=, /= and %=, each meaning "do this to the variable and keep the answer in it". If you have used another language you may reach for coins++. GDScript has no such thing; write coins += 1.

Comparing

extends Node

func _ready() -> void:
	var coins := 30
	var price := 18
	print(coins > price)
	print(coins == price)
	print(coins != price)
	print(coins >= 30)
	print("apple" < "banana")     # Strings compare letter by letter
	print("Wren" == "wren")       # ...and a capital is a different letter

A comparison is an expression too, and its value is a bool. There are six: == equal, != not equal, < and >, and <= and >= for "or equal". Keep hold of the difference from Chapter D: == asks, = stores.

and, or, not

Real questions have more than one part. Three words join bools into bigger bools:

extends Node

func _ready() -> void:
	var hour := 9
	var is_sunday := false
	var has_key := true
	print(hour >= 8 and hour < 18)        # and: both sides must be true
	print(is_sunday or hour >= 18)        # or: one side is enough
	print(not is_sunday)                  # not: the opposite
	print(has_key and not is_sunday and hour >= 8)

Set hour to 20 and predict all four lines before you look. (You will meet &&, || and ! in other people's code. They mean the same; the words are GDScript's habit.)

These have an order as well: comparisons are worked out first, then not, then and, then or. The last two are where people get caught, because English does not have the rule and GDScript does:

extends Node

func _ready() -> void:
	var is_member := true
	var has_ticket := false
	var is_banned := true
	print(is_member or has_ticket and not is_banned)       # the banned member walks in
	print((is_member or has_ticket) and not is_banned)     # what was meant

Without brackets, and is done before or, so the first line reads "a member, or else somebody with a ticket who is not banned". Whenever and and or share a line, put the brackets in.

if, elif, else: choosing what runs

So far every line of a script has run, top to bottom, every time. if makes a block of lines run only when a condition is true, and that is where a program starts to behave rather than recite.

extends Node

var coins := 30

func _ready() -> void:
	if coins >= 18:
		print("A carrot, please.")
		coins -= 18
	print("Coins left: ", coins)

The shape is if, a condition, a colon, and then a block one tab further in. The block is every line at that deeper indent, and it runs only if the condition is true. The last print is back at the outer indent, so it is not part of the block and always runs. Change coins to 10 and run it again.

The indentation is the code

In many languages blocks are marked with curly brackets and the indentation is for looks. In GDScript the indentation is the mark, so getting it wrong is getting the program wrong. There are three ways to do it, and you should see each once. Leave the block un-indented:

extends Node

var coins := 30

func _ready() -> void:
	if coins >= 18:
	print("A carrot, please.")

Godot expected an indented block after the if and found none. Forget the colon:

extends Node

var coins := 30

func _ready() -> void:
	if coins >= 18
		print("A carrot, please.")

Both of those are kind mistakes: Godot refuses to run and names the line. The third kind is not kind at all. This one runs:

extends Node

var coins := 10

func _ready() -> void:
	if coins >= 18:
		print("A carrot, please.")
	coins -= 18
	print("Coins left: ", coins)

Ten coins, no carrot, and eight coins of debt. The line that takes the money has slipped out of the block, so it runs whether or not anything was bought. Nothing is reported, because nothing is wrong as far as Godot can tell: the script does exactly what its indentation says. Press Edit and run and give that line one more tab. When an if misbehaves, look at the left edge before you look at the condition.

One more that every beginner types at least once:

extends Node

var coins := 30

func _ready() -> void:
	if coins = 30:
		print("Exactly thirty.")

A single = stores; it does not ask, and Godot will not let you store in the middle of a condition. The message for this does not always mention the equals sign, so when an if line is refused and looks right, count the equals signs.

Tabs, not spaces

Godot's editor indents with tabs, one per level, and pressing Tab with several lines selected moves them all. Do not mix tabs and spaces in one file: they can look identical and Godot treats the mixture as an error.

else and elif

else gives a block to run when the condition was false. elif, short for "else if", asks another question first. Together they make a ladder:

extends Node

var coins := 30

func _ready() -> void:
	if coins >= 100:
		print("rich")
	elif coins >= 20:
		print("comfortable")
	elif coins >= 1:
		print("getting by")
	else:
		print("broke")

Godot goes down the ladder from the top, runs the block of the first condition that is true, and skips all the rest. else catches whatever reached the bottom. Exactly one block runs, never two. Try 150, 5 and 0.

Because the first true rung wins, each rung can rely on the ones above it having failed. coins >= 20 is only ever asked when coins >= 100 was false, so it means "20 to 99" without having to say so. It also means the order is part of the logic. Set coins to 150, then swap the first two conditions (with their blocks) and run it: the wider question now sits on top and swallows everybody.

An if inside an if

A block can contain anything, including another if, one tab deeper again. That is fine for two levels. At three, stop and look for an and: if has_key and not is_night: says in one line what two nested ifs say in two, and keeps the code near the left edge where it is easy to read.

Choosing a value on one line

extends Node

func _ready() -> void:
	var coins := 30
	var mood := "pleased" if coins >= 20 else "worried"
	print(mood)
	print("1 coin" if coins == 1 else str(coins) + " coins")

this if condition else that is an expression: it does not choose which lines run, it chooses between two values, so it can go anywhere a value can. Keep it for short choices like these. Set coins to 1 and to 5.

What counts as true

An if wants a bool, but it will accept any value at all. Given something that is not a bool, it asks a simpler question: is this empty, or zero?

extends Node

func _ready() -> void:
	var player_name := ""
	var coins := 0
	if player_name:
		print("Hello, ", player_name)
	else:
		print("You have not told me your name.")
	if coins:
		print("You have money.")
	else:
		print("Not a coin.")

An empty String counts as false and so does zero. Type a name between the quotes and make coins 5, and both go the other way.

Use it where it reads like English: if player_name:, if not items:. For numbers, say what you mean. if lives: is true at -1, which is nobody's idea of having lives left; if lives > 0: is clearer and right.

and, or stop as soon as they know

extends Node

func _ready() -> void:
	var visits := 0
	var spent := 0
	if visits > 0 and spent / visits >= 3:
		print("A regular.")
	else:
		print("Not yet.")

Dividing by zero is an error, and visits is zero, yet this runs. When the left side of an and is false the answer is already false, so Godot never works out the right side. That makes and a guard: put the check that makes the second question safe on the left. Prove it to yourself – delete visits > 0 and and run it. or does the mirror image: if the left side is true, the right is never looked at.

in

extends Node

func _ready() -> void:
	print("ou" in "hours")
	print("z" in "hours")
	print(3 in [1, 2, 3])

in asks whether one thing is inside another, and gives a bool: a piece of text inside a String, or a value in a list. It saves writing day == 6 or day == 7 as the list of days grows.

match: one value, many branches

When one value decides between a handful of branches, a ladder of elif repeats the same comparison on every rung. match names the value once and lists what it might be.

extends Node

func describe(crop: String) -> String:
	match crop:
		"carrot":
			return "orange and patient"
		"tomato", "strawberry":
			return "red, and gone by Friday"
		"pumpkin":
			return "enormous"
		_:
			return "not something I grow"

func _ready() -> void:
	print(describe("carrot"))
	print(describe("strawberry"))
	print(describe("turnip"))

The value after match is compared with each pattern in turn, from the top. The first pattern that fits has its block run, and then the match is finished – it never carries on into the next branch. Several patterns separated by commas share a block. _ fits anything, so it goes last, as the "otherwise". If nothing fits and there is no _, nothing runs and nothing complains. Add a branch for "turnip".

A pattern can be any fixed value: a String, a number, a constant, and best of all an enum, since the list of names is exactly the list of branches:

extends Node

enum Weather { CLEAR, RAINY, SNOWY }

func advice(w: Weather) -> String:
	match w:
		Weather.RAINY:
			return "Take a coat."
		Weather.SNOWY:
			return "Take two."
		_:
			return "Go as you are."

func _ready() -> void:
	print(advice(Weather.SNOWY))
	print(advice(Weather.CLEAR))

Two things to know. match is fussier about types than ==: the int 1 does not fit the pattern 1.0. And a pattern is a value, not a question, so coins >= 100 cannot be one. For ranges there is a guard: var catches the value under a name and when adds a condition.

extends Node

func how_many(n: int) -> String:
	match n:
		0:
			return "nobody"
		1:
			return "one person"
		var crowd when crowd > 100:
			return "a crowd"
		_:
			return "a few people"

func _ready() -> void:
	print(how_many(0))
	print(how_many(7))
	print(how_many(500))

As a rule of thumb: reach for match when one value picks from a fixed set of alternatives, and for if and elif when the rungs ask different questions or compare against ranges.

Loops: for and while

The thing a computer is really good at is doing the same job again without getting bored or careless. A loop is a block that runs more than once.

for: once for each

extends Node

func _ready() -> void:
	for i in 3:
		print("knock ", i)
	for day in range(1, 4):
		print("Day ", day)
	for letter in "Wren":
		print(letter)

for name in something: runs its block once for each item in the something, and each time round the name holds the next item. What the items are depends on what you loop over:

  • A number, for i in 3, counts 0, 1, 2: from zero, stopping before the number. Three times round, but the last value is 2.
  • range(1, 4) counts from the first number up to, but not including, the second: 1, 2, 3. A third number is the step, so range(0, 10, 5) is 0, 5 and range(3, 0, -1) counts down 3, 2, 1.
  • A String gives its characters one at a time. A list gives its items – that is most of Chapter G.

Change range(1, 4) so it prints days 1 to 7. The off-by-one is the mistake to expect: the end of a range is never included.

Building up an answer

extends Node

func _ready() -> void:
	var total := 0
	for n in range(1, 11):
		total += n
	print(total)

This shape comes up constantly: a variable made before the loop, changed inside it, and read after. The variable has to be made outside, because one made inside the block is local to the block and starts afresh every time round. The same shape counts things (count += 1 inside an if) and finds the biggest.

break and continue

extends Node

func _ready() -> void:
	for day in range(1, 15):
		if day % 7 == 0:
			continue        # skip this one: straight on to the next day
		if day > 10:
			break           # stop the whole loop, now
		print("Work day ", day)

continue abandons this turn of the loop and starts the next. break leaves the loop altogether. Day 7 is skipped and the loop is over at 11, though the range ran to 14. Putting continue at the top of a block for "nothing to do here" keeps the real work from being wrapped in an if; you will see Little Hours do it below.

while: for as long as

for is the loop for when you know what you are going through. Sometimes you only know when to stop. while repeats its block for as long as a condition stays true, checking before every turn:

extends Node

func _ready() -> void:
	var coins := 3
	var days := 0
	while coins < 50:
		coins *= 2
		days += 1
	print("After ", days, " days: ", coins, " coins")

Nobody told the loop to run five times; it ran until doubling had taken the coins past 50. Change the 50 to 1000.

The danger is plain: if nothing in the block ever makes the condition false, the loop never ends.

extends Node

func _ready() -> void:
	var coins := 3
	var days := 0
	while coins < 50:
		days += 1
	print(days)

This page gives up after a moment and says so. Godot does not: the game freezes, the window stops answering, and there is no error to read, because nothing has gone wrong except that it will never finish. Every while needs a line inside it that moves towards the condition being false. Before you run one, find that line.

The game is already a loop

You never write while true: to keep a game going. Godot runs the big loop itself and calls your _process() once every frame (Chapter I). The loops you write are small ones that finish inside a single frame: over the plots of a farm, the letters of a line, the days of a week.

Build it live

Operators, a ladder, a match, a for and a while, each doing one job in the same small program: an almanac that knows the season and the sky for any day you ask about.

In Little Hours

The game keeps one number for the time of day and one for the day itself. Nearly everything the player reads off the screen – the clock, the phase, the season, the sky – is an expression or a decision made from those two, each time it is wanted.

The clock: / and %

Game.gd · lines 1268–1271

func clock_text() -> String:
	# 06:00 at sunrise through 22:00 at nightfall.
	var mins := int(lerpf(360.0, 1320.0, day_fraction()))
	return "%02d:%02d" % [(mins / 60) % 24, mins % 60]

day_fraction() is how far through the day it is, from 0.0 at sunrise to 1.0 at nightfall. lerpf(360.0, 1320.0, f) turns that share into minutes since midnight: 360 is 06:00 and 1320 is 22:00. int() cuts it to whole minutes, and then the two halves of division split it exactly as you split 135 minutes: mins / 60 for the hour, mins % 60 for the minutes past it. The extra % 24 wraps the hour round a 24-hour face, and "%02d:%02d" is the format string from Chapter D that gives 09:05. The whole clock is in C: Clock.

The phase: a ladder without elif

Game.gd · lines 1258–1263

func phase() -> String:
	var f := day_fraction()
	if f < 0.2: return "Morning"
	if f < 0.55: return "Daytime"
	if f < 0.75: return "Evening"
	return "Night"

Four rungs, written as one-line ifs. There is no elif and no else, because each rung returns: once a return runs the function is over, so the next line is only reached when the one above was false. It is the same ladder, and it leans on its order in the same way – f < 0.55 means "between 0.2 and 0.55" only because the first rung has already taken everything below 0.2. The last line is the else.

The way you chose to play: match

At the start the player picks a way to play, kept as a String (B: Beginning). A match turns it into a number:

Game.gd · lines 3265–3270

## How fast the day runs. Cosy days are longer, so there is time to potter.
func mode_day_scale() -> float:
	match mode():
		"cosy": return 0.8
		"hustle": return 1.15
		_: return 1.0

Each branch is short enough to sit on its pattern's line. _ covers every other mode, and also a mode nobody has invented yet, so the function always has an answer. The number is used where the clock is counted: clock_t += delta * mode_day_scale(), so a cosy day runs at four fifths of the speed and lasts longer.

The farm: a loop that skips

Game.gd · lines 450–473

## A watered crop ripens on its own after its grow time, so the farm rewards you
## for coming back later in the same day — you don't have to sleep to see it.
## Only writes to disk on the frame a plot actually flips, never every frame.
func _tick_farm() -> void:
	var changed := false
	for plot in (state["farm"] as Array):
		if plot["state"] != "planted" or not plot["watered"] or plot["ready"]:
			continue
		var crop := str(plot["crop"])
		if not CROPS.has(crop):
			continue
		var grow := float((CROPS[crop] as Dictionary)["grow"])
		# The clock starts again every morning and whenever the game is opened,
		# and it is not saved: a time from before that is later than now, and
		# a crop planted in the evening would wait all of the next day for the
		# clock to catch up. It has been in the ground since before today.
		if float(plot["planted_at"]) > clock_t:
			plot["planted_at"] = 0.0
		if clock_t - float(plot["planted_at"]) >= grow:
			plot["ready"] = true
			changed = true
	if changed:
		farm_updated.emit()
		save_now()

This runs every frame, and it is everything this chapter covered in twenty lines. A for goes through the farm's plots. The first if joins three conditions with or and not – not planted, or not watered, or ripe already – and any one of them means there is nothing to do, so continue moves on to the next plot. A second continue guards against a crop the game does not know. What is left is the real question, a comparison between two floats: has this crop been in the ground for its growing time? changed is a bool made before the loop and set inside it, the build-up-an-answer shape, so that the save happens once after the loop however many plots ripened – and, as the comment says, never on a frame when none did. The farm's rules are in F: Farming.

The sky is decided the same way. weather() in the same file turns the day number into a share between 0 and 1, then uses an if for winter and the one-line "Rainy" if r < rain_chance else "Clear" for the other seasons; because it is worked out from the day alone, the same day always has the same weather (W: Weather and seasons). Inside the code has the rest of Game.gd.

Six exercises. The first asks you to think before you run; the second hands you somebody else's bug.

What to remember

  • An expression is anything with a value. / and % are the two halves of whole-number division; % splits units, tests divisibility and wraps round.
  • Comparisons give bools; and, or and not join them. and is done before or, so use brackets when both appear, and both stop as soon as the answer is known.
  • if, elif, else run the first block whose condition is true, so order matters. The block is whatever is indented – a wrong indent is a wrong program, and often a silent one.
  • Zero, empty and null count as false; everything else counts as true.
  • match compares one value with a list of patterns and runs the first that fits; _ fits anything and goes last.
  • for goes through things you already have – and range(1, 11) stops at 10. while runs until a condition fails, and needs a line that makes it fail.
