Getting it in front of people

A game nobody can run is a hobby, which is a perfectly good thing to have. But the distance between "runs on my machine" and "runs on a stranger's" is smaller than it looks, and worth crossing at least once.

Export templates come first

Nothing exports until you have them, and the error message when you do not is not especially helpful.

Godot ships as a small editor. The actual runtimes for each platform — Windows, macOS, Linux, Android, iOS, web — are downloaded separately and must match your Godot version exactly. A 4.7 project cannot export with 4.6 templates.

Editor → Manage Export Templates → Download and Install. It is about a gigabyte and you only do it once per Godot version.

Then: Project → Export

Add a preset per platform. The important fields are the same everywhere:

  • Export Path — where the file lands. Put builds in a folder your version control ignores.
  • Resources — what gets packed. The default (everything) is right until your project is large.
  • Features / tags — how OS.has_feature() answers, if you branch behaviour per platform.

Then Export Project for a real build, or Export PCK/ZIP if you only want the data.

Test the export, not the editor

Running from the editor and running an exported build are not the same thing. Missing resources, case-sensitive path bugs and files that were never imported all show up only in the build. Export early, once, before you have a hundred assets — the first export always finds something.

The web, which is where people will actually play it

A link somebody can click is worth ten downloads they will not. Godot 4 exports to WebAssembly and WebGL 2, but requires the Compatibility renderer and a browser with WebGL 2 support enabled.

If your project uses Forward+ or Mobile, switch to Compatibility before exporting to Web. Even a current browser may not have WebGL 2 available, depending on the hardware and browser settings.

What you get

A Web export produces a handful of files — an index.html, a .wasm, a .pck with your game data, and some JavaScript glue. All of them must be served together, from a web server. Opening index.html off your disk will not work: browsers refuse to load WebAssembly over file://.

To try it locally, serve the folder:

python3 -m http.server 8000
# then open http://localhost:8000

Publishing on itch.io

itch.io is free, takes browser games natively, and is where most small games live. The process, in order:

  1. Export to Web into an empty folder.
  2. Zip the contents of that folder, not the folder itself. index.html must be at the top level of the zip — this is the single most common mistake.
  3. On itch.io: Create new project, set Kind of project to HTML.
  4. Upload the zip and tick This file will be played in the browser.
  5. Set the viewport size to your game's resolution, and turn on SharedArrayBuffer support in the embed options if your export uses threads.

The black-screen checklist

A web build that worked locally and shows nothing on itch is almost always one of three things: index.html is not at the root of the zip; the export used threads but SharedArrayBuffer support is off; or the export templates did not match the editor version. Check the browser console first — Godot prints a real error there.

Since Godot 4.3 the single-threaded web export is the default, which avoids the SharedArrayBuffer problem entirely. Leave it that way unless you have a specific reason.

What web export costs you

Not everything survives the trip. There is no filesystem, so user:// is browser storage and clearing site data wipes saves. Threads and some audio features are restricted. Load times are real — a large .pck is a download before anything happens. And on mobile browsers, performance is noticeably worse than a native build.

For a game like the one in this book — 2D, a few thousand sprites, no physics — none of that bites. For anything heavier, ship desktop first.

Desktop and mobile, briefly

Desktop

Windows, macOS and Linux export with no ceremony. Two wrinkles worth knowing before you send a build to somebody:

  • macOS gatekeeping. An unsigned .app gets refused by default on somebody else's Mac. They can right-click → Open to get past it, but if you are distributing seriously you want an Apple Developer account and notarisation.
  • Windows SmartScreen. An unsigned .exe shows a warning the first time. A code-signing certificate removes it; most small games simply live with it.

Android

Needs the Android SDK and a keystore. The debug keystore is generated for you; a release keystore you make yourself, and losing it means you can never update that app on Google Play again. Back it up somewhere that is not your laptop, on the day you create it.

iOS

Exports an Xcode project rather than a finished app. You need a Mac, Xcode, and an Apple Developer account to put it on a device that is not your own.

Licensing, which is duller than it is optional

Two questions, and the second one is where people get caught.

Godot itself

MIT licensed. You can ship commercial games, keep all the money, and you owe nobody a royalty. You do have to include the engine's copyright notice — Godot generates it for you, and the polite thing is a Credits screen or a line in the readme.

Everything you did not make

Sprites, fonts, music, sound. Each one has a licence and they are all different. The three that matter:

Licence typeWhat it means in practice
CC0 / public domainDo anything. Attribution is polite, not required.
CC-BYDo anything, but credit the author by name, visibly.
Personal use onlyNot in anything that makes money, ever. This includes a free game with ads and a game you sell for a pound.

A live example from this project

The typeface Tiny Home uses, Lower Pixel, is licensed personal use only. That is completely fine as things stand — it is a personal project. But it is exactly the kind of thing that is easy to forget two years later when you decide to put the game on itch for money. Keep a CREDITS.md listing every asset and its licence, and write the line the day you add the asset, not the day you ship.

The habit worth forming

One file, in the repository, updated as you go:

## Art
LimeZu — Modern Interiors, Modern Exteriors — purchased, commercial use OK

## Fonts
Lower Pixel — IbraCreative — PERSONAL USE ONLY, must be replaced before selling

## Engine
Godot 4.7 — MIT

Five minutes now, versus an afternoon of archaeology later.
